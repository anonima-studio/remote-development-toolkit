# Remote development toolkit

> Перевод. Источник: [README.md](../../README.md). При расхождении верен
> английский текст.

**Remote development toolkit by Anonima Studio.** Автор: Yury Telitsin.

Набор скриптов, который превращает один сервер Ubuntu в хост удалённой
разработки для AI-агентов и их нагрузки. Рабочими пространствами (workspaces)
управляет [Coder](https://coder.com) Community; этот репозиторий отвечает за
воспроизводимое развёртывание хоста, ограниченный Docker-шаблон workspace,
проверки оператора и контракт восстановления. Точка входа — команда
`remote-dev`, которая запускается на Mac.

## Зачем

AI-агенты хорошо правят код и плохо управляют инфраструктурой. Сборки, тесты,
установка зависимостей и Docker-стеки агента на ноутбуке конкурируют со всем
остальным; перенос всего на сервер отрывает агента от skills, MCP-серверов,
учётных данных и подтверждений, которые оператор настроил локально. Большинство
удалённых схем к тому же смешивают три вопроса, которые здесь разделены:

- **Где работает агент?** На Mac или в workspace — выбирается для каждого
  проекта.
- **Какая копия исходников авторитетна?** Ровно одна для каждой рабочей копии,
  без двух записываемых копий, синхронизируемых в обе стороны.
- **Что считается готовым?** Результат, который пользователь может открыть у
  себя, а не `localhost` внутри удалённого контейнера.

Методология, которая отвечает на эти вопросы, называется **local agents,
remote execution** («локальные агенты, удалённое исполнение»). Правила и
файлы или тесты, которые их обеспечивают: [methodology.md](methodology.md).

## Статус

Публикуется как портфолио и продукт «как есть». Уровни зрелости:

- **stable** — интерфейс устоялся, покрыт автоматическими тестами, автор
  пользуется им в ежедневной работе;
- **beta** — реализовано и покрыто тестами; интерфейс или процедура могут
  измениться;
- **prototype** — механизм есть, но его сквозная процедура не отрепетирована в
  рамках этого выпуска.

| Компонент | Зрелость | Как проверяется |
| --- | --- | --- |
| Подготовка хоста (`bootstrap/ubuntu.sh`) | stable | Проверка shell в CI; первый шаг quickstart на новом сервере |
| Развёртывание Coder, `install`, `doctor`, `status`, `audit` | stable | Smoke-тест CLI на синтетических профилях в CI; `doctor` на вашем хосте |
| Запуск одной командой (`quickstart`, `init`) и минимальная топология | beta | Тесты топологий профиля и smoke-тест CLI в CI; серверная часть проверяется самим quickstart, который завершается `doctor` |
| Расширенная топология (Cloudflare Tunnel + WireGuard) | beta | Тест сетевого контракта в CI; проверки `doctor` на вашем хосте |
| Docker-шаблон workspace | stable | Сборка образа на Linux, проверка hash, тесты workspace, ролей и удержания образов в CI |
| Режим `remote` с адаптером Codex (необязательным) | stable | Smoke-тесты Codex и Codex Desktop в CI |
| `preview`, `debug-forward`, `project-setup`, `worktree-vars` | stable | Smoke-тесты в CI |
| Передача секретов по манифестам | beta | Тесты на синтетических данных в CI |
| Режим `local-agent` | beta | Тесты жизненного цикла, MCP, working set и восстановления в CI с поддельными Coder и Mutagen |
| Переключение режимов (`mode`) | beta | Тесты с настоящим Git и имитацией транспорта в CI |
| Автоматическая подготовка workspace при переключении | prototype | Тесты в CI; не отрепетировано на живом развёртывании |
| Передача пароля владельца (`credentials`) | beta | Smoke-тест в CI |
| Точечные обновления Codex | beta | Тесты в CI |
| Резервное копирование вне хоста (`backup/`) | prototype | Только проверка shell; восстановление в рамках выпуска не репетировалось |

CI запускает `pnpm lint` и `pnpm test` на macOS для каждого push и pull request
и сканирует репозиторий на секреты.

## Быстрый старт

Нужны Mac с Coder CLI, Git, Python 3 и SSH-клиентом и новый сервер Ubuntu
24.04 или 26.04, на который можно войти по ключу под `root` (или под
пользователем с `sudo`). Подробно: [quickstart.md](quickstart.md).

```bash
git clone https://github.com/anonima-studio/remote-development-toolkit.git remote-dev && cd remote-dev
bin/remote-dev quickstart example-profile --ssh root@<ip-сервера>
```

Команда готовит и защищает сервер, пишет профиль хоста с минимальной
топологией, устанавливает Coder и запускает `doctor`. Первый запуск занимает
15–30 минут: основное время уходит на обновление системы и сборку образа
workspace. Если сервер принимает не ваш ключ по умолчанию, добавьте
`--admin-key <путь>`. Затем:

```bash
bin/remote-dev --profile example-profile forward          # оставить работать
bin/remote-dev --profile example-profile credentials reveal coder \
  --confirm-profile example-profile                       # во втором терминале
```

Откройте <http://127.0.0.1:3080>, войдите как владелец и создайте workspace из
шаблона **Remote Dev Docker**.

## Режимы разработки

| Режим | Агент, его skills, MCP, учётные данные | Авторитетный Git checkout | Зависимости, сборка, тесты, запуск, отладка, Docker |
| --- | --- | --- | --- |
| `remote` | Workspace разработки в Coder | Тот же workspace | Тот же workspace |
| `local-agent` | Mac | Mac (один Git-корень или явный working set) | Отдельный runner-workspace в Coder |

У каждого workspace одна неизменяемая роль (`development` или `runner`);
режимы никогда не делят workspace. Переключение проекта между режимами — явная
операция с журналом. Интеграция с Codex — необязательный адаптер.

Подробности на английском: [Local Agent mode](../local-agent-mode.md),
[Mode switching](../mode-switching.md), [Codex on Coder](../codex-on-coder.md).

## Поддержка

Предоставляется «как есть», без SLA. Issues приветствуются; pull requests
рассматриваются на усмотрение автора. Об уязвимостях сообщайте приватно:
[SECURITY.md](../../SECURITY.md).

Плановые обновления зависимостей — ежемесячно, в первый день месяца по UTC;
исправления безопасности — сразу. Renovate создаёт отдельный PR на семейство
компонентов; автор проверяет CI и принимает изменения. CI сохраняет проверки
macOS и gitleaks, собирает workspace image на Linux без публикации и проверяет
Coder Compose с примером окружения.

Pins фиксируют содержимое upstream-образов через digest, версии устанавливаемых
пакетов и дерево npm через lockfile. Hash исходников связывает Dockerfile и
helpers с tag шаблона. Это делает обновления явными и проверяемыми, но не
гарантирует отсутствие уязвимостей или неизменность apt-пакетов из Ubuntu.
Текущие версии указаны в
[`templates/docker/Dockerfile`](../../templates/docker/Dockerfile) и
[`deploy/coder/compose.yaml`](../../deploy/coder/compose.yaml).

Версию Codex можно выбрать отдельно для workspace (подставьте явную версию,
профиль и workspace):

```bash
bin/remote-dev --profile example-profile codex-update my-app --version <version> --check
bin/remote-dev --profile example-profile codex-update my-app --version <version> --restart
```

Проверка показывает текущую и целевую версии и требования. `--restart` печатает
receipt, перезапускает workspace и проверяет установленную версию. Другие workspace и pin образа не
меняются. Завершите активные сессии перед `--restart`; используйте его, когда допустим
перезапуск. Если мешает требование или существующий receipt, следуйте руководству
по восстановлению перед повтором. Повторите `--check` после обновления.
Восстановление: [workspace-updates.md](../workspace-updates.md).

После изменения входных файлов образа запустите `pnpm image:hash` в корне
репозитория и закоммитьте изменённые pins. `pnpm image:hash --check` и `pnpm test`
отклоняют устаревший hash и показывают команду исправления. Полная
[политика обновлений](../../SUPPORT.md#dependency-updates).
